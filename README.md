## VPS延迟测试到底测什么？三个指标说清楚

核心就三个指标：Ping值、丢包率、抖动。Ping值是你发一个包到服务器再等回应的时间；丢包率是路上被丢掉的包的比例；抖动反映多次延迟之间的波动。

各地区正常水平心里要有数：国内服务器一般几十毫秒，日韩、新加坡大概100多毫秒，美国和欧洲得200毫秒往上。同一档位里，越低越好。

不过Ping值低不代表一定快。真正致命的是丢包率——网络拥堵时，中间的路由器会开始丢包，丢包率超过5%，这台机器基本可以判死刑。有时候Ping值不高、用着就是卡，多半是丢包在作祟。

时间点也有讲究：晚上八点到十点才是测试的黄金时段。白天线路空闲，怎么测都好看；晚高峰扛得住，才说明这台VPS是真稳。

## 不敲命令行：网页工具版延迟测试

不想碰终端，几个网页工具就能覆盖大半需求。

| 工具 | 测什么 | 重点看什么 |
| --- | --- | --- |
| ping.pe | 全球多节点连续Ping | 大陆方向平均延时、晚高峰丢包率、IP有没有被墙 |
| itdog.cn 的 TCPing | 用TCP协议测延迟 | 比普通Ping更接近真实使用 |
| itdog.cn 的路由追踪 | 去程路由 | 路径有没有绕路 |
| tcp.pine.pe | TCP端口连通性 | 端口通不通 |

ping.pe 能从全球多个位置连续Ping你的服务器，实时显示延时、丢包率和图表，比自己手动ping一次靠谱得多。重点看两行：大陆地区的平均延时，以及晚高峰的丢包率。后者最关键——晚上八九点测出来丢包率还是0，基本就是良心货。

TCPing值得单独说一句。运营商有时候会给ICMP Ping“开小灶”，Ping测试看着很美，实际使用完全两回事。TCPing走TCP协议，更贴近真实业务表现。两组数据对不上时，信TCPing。

去程路由用 itdog.cn 的 tracert 就能看。但去程只是半张图，另一半要靠下面的脚本。

## 回程路由测试：延迟之外最该看的一项

回程路由最能暴露线路的真面目。原因很直接：你访问网站时请求很小，服务器返回的数据量大得多，回程线路才决定实际体验。有些商家只优化去程，回程还是普通线路，典型的挂羊头卖狗肉。

在VPS上跑一行命令，直接显示回程线路：

bash
curl https://raw.githubusercontent.com/zhucaidan/mtr_trace/main/mtr_trace.sh|bash


想自动测完电信、移动、联通和教育网四个方向，用 autobesttrace：

bash
wget -qO- git.io/autobesttrace | bash


结果对照这张表读：

| 只有去程有 59.43 | CN2 GT（回程仍走普通线路） |

| 219.158.*.* | 联通骨干（AS4837） |

好线路贵有贵的道理，好比高速公路和省道的差别。但别光听商家自夸，脚本一跑，回程里有没有59.43一目了然。

## 延迟测试常见问题

**VPS延迟多少毫秒算正常？**
国内服务器几十毫秒，日韩、新加坡100多毫秒，美国、欧洲200多毫秒。同档位越低越好，但Ping值只是参考，丢包率更致命。

**为什么白天测很快，晚上就卡？**
晚高峰网络拥塞，路由器开始丢包。白天线路空闲，数据普遍偏好，所以延迟测试必须放到晚八点到十点复测才算数。

**Ping值很低但用着卡，是什么原因？**
大概率是丢包，或者运营商对ICMP做了优化。换TCPing测一遍，如果TCPing的延迟和丢包明显更差，以TCPing为准。

**怎么确认商家说的CN2是真的？**
跑回程路由脚本，看有没有59.43开头的IP。去程回程都有是CN2 GIA，只有去程是CN2 GT，全是202.97那就是普通163线路。
